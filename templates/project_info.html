Project Executive Summary

The AWS Cloud Internship Project delivers a robust, scalable, and secure Student Internship Portal deployed on a Linux Amazon EC2 instance inside a custom-configured Amazon Virtual Private Cloud (VPC).

Designed to adhere to the AWS Well-Architected Framework across Operational Excellence, Security, Reliability, and Cost Optimization, this architecture decouples networking layers, relies strictly on temporary IAM credentials, and maintains automated snapshot backups for zero-data-loss disaster recovery.

Core Deliverables Achieved:
  • Custom VPC CIDR 10.0.0.0/16 with public subnet 10.0.1.0/24
  • EC2 Linux Web Server running Flask & Gunicorn behind Nginx
  • Amazon S3 private bucket storage with IAM instance profiles
  • Amazon CloudWatch metric alarms (CPU > 70%, StatusCheckFailed)
  • Amazon SNS email alerts for incident dispatch
  • EBS automated volume snapshot backup and restore drill
  • AWS Budgets threshold governance ($1.00 USD/month safeguard)
Security Design: IAM Roles vs Access Keys

A paramount security requirement of this deployment is the absolute prohibition of hardcoded AWS Access Keys (AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY) within source code, configuration files, or server environments.

Security Dimension Hardcoded Access Keys IAM Instance Profile (Adopted)
Credential Lifespan Permanent until manual rotation Automatically rotated STS tokens
Leakage Risk Catastrophic if pushed to GitHub Zero credentials stored on disk
Scope of Access Often over-permissioned Least-privilege scoped to project bucket
Auditability Difficult to trace Native CloudTrail integration

The EC2 instance requests temporary credentials dynamically via the AWS Instance Metadata Service v2 (IMDSv2), eliminating static credential compromise vectors entirely.

Comprehensive Architecture

AWS Services Configuration Details

1. Custom AWS VPC & Networking
Amazon Virtual Private Cloud
  • VPC CIDR Block: 10.0.0.0/16 providing 65,536 private IP addresses.
  • Public Subnet: 10.0.1.0/24 located in availability zone ap-south-1a with Auto-assign Public IPv4 enabled.
  • Internet Gateway (IGW): internship-igw attached to the custom VPC to provide bidirectional Internet routing.
  • Route Table: internship-public-rt configured with default destination 0.0.0.0/0 targeted at internship-igw.
  • Security Group: internship-web-sg allowing Inbound Port 80 (HTTP) globally and Inbound Port 22 (SSH) strictly from administrator IP.
2. Amazon EC2 Linux Web Host
Elastic Compute Cloud
  • Instance Type: t2.micro (1 vCPU, 1 GiB RAM) Free Tier eligible compute.
  • Operating System: Ubuntu 24.04 LTS (HVM) with 64-bit x86 architecture.
  • Web Server Stack: Python 3 Flask web application served via Gunicorn WSGI running as a persistent systemd daemon service.
  • Reverse Proxy: Nginx receiving public traffic on Port 80 and reverse-proxying internally to Gunicorn on 127.0.0.1:5000.
  • Health Checks: Integrated /health endpoint for uptime and ELB health verification.
3. Amazon S3 Object Storage
Simple Storage Service
  • Bucket Access: 100% Private bucket with Block Public Access enabled across all 4 settings.
  • Storage Hierarchy: Organized prefixes: /logs/, /datasets/, /backups/, and /assets/.
  • Permissions: Scoped strictly to the EC2 IAM Instance Profile using policy InternshipS3LeastPrivilegePolicy.
  • Data Protection: Server-Side Encryption (SSE-S3 AES-256) enabled by default.
4. CloudWatch Alarms & SNS Alerts
Monitoring & Incident Dispatch
  • High CPU Alarm: Triggers when EC2 metric CPUUtilization > 70% for 1 consecutive period of 5 minutes.
  • Status Check Alarm: Triggers when metric StatusCheckFailed >= 1 for 1 minute (system or instance failure).
  • SNS Topic: internship-alerts-topic broadcasting instant alert payloads.
  • Email Subscription: Direct notification sent to madhumitha19022@gmail.com with one-click email confirmation.
5. EBS Snapshots & Disaster Recovery
Elastic Block Store Point-in-Time Backup
  • Point-in-Time Backup: Snapshot taken of the root EBS volume capturing OS, dependencies, and configuration.
  • Tagging: Name: Internship-Portal-Root-Backup, Environment: Production.
  • Restore Procedure: Create a new EBS volume from snapshot → attach to EC2 or launch replacement instance with identical state.
6. AWS Budgets & Cost Control
Financial Governance & Free Tier Compliance
  • Cost Limit: Strict monthly budget limit established at $1.00 USD.
  • Threshold Alerts: Email triggered when actual spend reaches 80% ($0.80) and 100% ($1.00).
  • Free Tier Adherence: Deliberately omitted chargeable managed resources: zero NAT Gateways ($32/mo saved), zero ALBs ($18/mo saved), and zero managed RDS databases.

Step-by-Step Implementation Workflow

1
Network & Security Setup

Provision custom VPC, create public subnet, instantiate Internet Gateway, build route table with 0.0.0.0/0 route, and define security groups with least-privilege ingress.

2
Compute & App Deployment

Launch Ubuntu t2.micro EC2, attach IAM instance role, clone GitHub repository, configure systemd Gunicorn service, and configure Nginx reverse proxy.

3
Monitoring & Governance

Set up S3 storage bucket, create CloudWatch CPU & status check alarms with SNS email triggers, take root volume EBS snapshot, and set up AWS Budget alert.
